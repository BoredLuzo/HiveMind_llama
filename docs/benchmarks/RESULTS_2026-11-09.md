# Benchmark Results - 2026-11-09 (core coder vs. Aider)

Environment: `qwen3.5:4b-mtp` (Q4_K_M, Vulkan, llama-server b12001),
HiveMind dev tree, Aider 0.86.2 in its own venv. Same model and server for
every cell; hidden tests; fresh workspace per cell; one run per task/condition
(21 tasks, 42 cells). Coder tier pinned to `duo_core` (17 tools), planner off,
agentic mode on, coder ctx 32768, test-feedback loops off.

## Headline

| Condition | Pass | 95% CI | Median | Tokens/cell |
|---|---:|---|---:|---:|
| `hivemind_duo` (core, coder alone) | **19/21 (90.5%)** | [71, 97] | **54.3 s** | **66,089** |
| `aider` | **19/21 (90.5%)** | [71, 97] | **22.1 s** | **970** |

Paired (majority): Aider-only 2 tasks, HiveMind-only 2 tasks,
McNemar p = 1.0. On this corpus the two agents are tied in quality.

## What the core tier changed

Compared with the 2026-11-08 full-tool coder run (20/21, 58.7 s median,
108,378 tokens/cell):

- tokens/cell: 108,378 -> 66,089 (**-39%**)
- median time: 58.7 s -> 54.3 s (**-7.5%**)
- pass rate: 20/21 -> 19/21 (one task: `multi_move`)

This is not a clean A/B: the older run had test-feedback on and a different
tool schema, and each cell has one run. Directionally, `duo_core` cuts roughly
two-fifths of the token cost without a measurable quality loss at this sample
size.

## Why the coder still uses ~68x Aider's tokens

- The 17-tool schema is **11,259 chars ≈ 2.8k tokens per round**
  (`schema_chars=11259` in `TOOL-CALL-MISS` telemetry). Aider sends a much
  smaller prompt and edits through its own format.
- A tool task runs 4-10 rounds. Every round re-sends the conversation; the
  benchmark sums `prompt_tokens` from every round, including cached prefixes.
  Aider reports one request/response pair.
- Cached prefill keeps wall time at ~2.5x Aider even though token count is
  ~68x: most of the repeated prompt is served from the KV cache.
- On these small synthetic tasks the tool loop is pure overhead. It has to
  earn its cost on larger/ambiguous work where exploration and verification
  matter.

## Caveat found by the live smoke

At coder ctx 8192 with the shipped agent budget (`duo_coder.max_tokens=16000`),
every tool round used to trip the `[CTX-FULL]` guard and force-compress; the
run could end in `loop_detected` after the model repeated a verification call.
This was fixed on 2026-11-09 (no duplicated system prompt, calibrated 1.05
factor, context-aware minimum budget). `tests/live_smoke.py --ctx 8192` now
passes in 29.2 s without compression storms. The default remains 16384.

## Later three-way run (2026-11-09)

After the fixes, a second 21-task run compared `duo_core` (17 tools),
`duo_lean` (10 tools) and Aider. All three tied at **19/21 (90.5%)**. Core
stayed faster than lean: median 35.8 s vs. 52.7 s; net tokens were 64,072 vs.
62,092 (-3.1%). The 17-tool core tier is the baseline; `duo_lean` is not
worth keeping as a default.

**Important:** an external GPU load started around `feature_flatten` during
that run, so all timings from that point are invalid for comparison, and
pass/fail after it may be affected. The clean 4-task multi-file run
(`multi_config`, `multi_move`, `multi_shape`, `multi_wire`) was 4/4 for core,
lean and Aider; use it for multi-file conclusions until the four failed
tasks are retried without GPU load.

## Limits

- One 4B model, 21 synthetic tasks, one run per cell. No claim about larger
  models or real repositories.
- Aider uses the same model and server but a different edit strategy; same
  model is not the same agent.
- Token units differ (HiveMind sums per-round prompt+completion; Aider reports
  its own sent/received counts). See `TOKEN_EFFICIENCY.md`.
