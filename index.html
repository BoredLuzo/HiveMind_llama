Compression & Context Fixes

      
Compression model

      
      
Auto (Coder) = the coder model summarizes. Selecting a model uses it as the light summarizer; it falls back to the coder when VRAM is tight.

      

      

        Error-Rollup
        
      

      
When the same test/compile error repeats across fix rounds, the coder sees "still failing since attempt #N" instead of the full error text again — saves context without hiding new errors (exact-match detection, no LLM).

      

        Pin repo-map into system
        
      

      
Keeps the repo-map in the cache-stable system prefix — after compression the model still sees the code map without a full re-prefill (biggest single cache saver on large repos).

      

        Write-Guard
        
      

      
write_file on existing files only after read_file.

      

        No-Op hint
        
      

      
Injects a read_file nudge after 2 ineffective edits on the same file.

      

        Wedge handoff BETA
        
      

      
Beta — on by default. When the coder fails the same edit on one file 4x in a row (or repeats one failing command), a fresh-context repair agent takes over that one edit (same model, clean window, max 2 per run). Switch it off here or set duo_wedge_handoff_enabled to false; watch for the "Wedge handoff" log line to see whether it did anything.

      

        Partial compression
        
      

      
Condenses only the old context; the recent tail stays byte-identical, so llama.cpp reuses the cached prefix (typical 80-100% cache reuse per round instead of a full re-prefill — visibly faster rounds on 32k+ contexts).

      

        Local-only summary
        
      

      
Compresses without calling an LLM: instead of a generated summary, old context is dropped and replaced by short recall markers. Result: compression takes <1s instead of minutes and never breaks the cache. Trade-off: the older part of the task is reduced to headlines — best when your compression model is slow or you prefer speed over long-term recall.

      
Flags apply on the next run (Write/No-Op guards also live). Balance check: compression runs at 70% context; with an 8k coder budget a 32k context has ~10k headroom per cycle — raise the context instead of the budget if you see frequent compressions.

Keep-Alive / Pinning

      

        Pin direct (after response)
        
      

      
ON = direct model stays in VRAM after a simple answer (no reload on next request).
Useful only in chat mode — in pipeline mode VRAM is needed by agents.

      

        Keep judge warm (after response)
        
      

      
OFF = judge is not re-pinned after each answer — saves VRAM if judge is rarely used.

      

        Unload coder after run
        
      

      
What happens to the coder's model slot when a run ends. OFF: the slot stays warm for the next prompt (the Coder TTL under Advanced decides when it is released) — follow-ups reuse the KV cache and start faster. ON: the slot is released at the end of the run (also on abort), so the next prompt reloads the model and re-prefills the whole context first (slower, but frees VRAM).
